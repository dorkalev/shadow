# P6.2 — Record of Authorized Disclosures

## Criterion (AICPA TSP Section 100, verbatim)
> The entity creates and retains a complete, accurate, and timely record of authorized disclosures of personal information to meet the entity's objectives related to privacy.

## What it means
The Privacy category is optional — it applies only if the company includes Privacy in its SOC 2 scope (most tiny startups don't; they cover privacy via GDPR/CCPA programs instead).

If Privacy is in scope, this criterion requires a running log of every *authorized* disclosure of personal information to third parties: what data was shared, with whom, when, under what consent or legal basis, and who authorized it. "Complete, accurate, and timely" means entries are made when disclosures happen, not reconstructed at audit time.

For routine, systematic sharing (e.g., every user record flows to your email provider), the register entry can describe the ongoing flow rather than logging each API call. Ad hoc disclosures — a one-off data export to a partner, a compelled legal disclosure, a customer-requested transfer — need individual entries. The auditor tests that the log exists, is maintained through the period, and matches reality.

## Points of focus (2022 revision, summarized)
Summarized from the AICPA 2022 points of focus:
- A record of authorized disclosures is created at or near the time of disclosure.
- The record identifies the recipient, the PI disclosed, the date, and the authorization/consent basis.
- Records are retained per the entity's retention policy.
- The record is periodically reviewed for completeness and accuracy.
- Systematic/recurring disclosures are documented as data flows; ad hoc disclosures are logged individually.

## What the auditor will ask for
- The disclosure log/register covering the full audit period.
- A sample of log entries traced to supporting evidence (consent record, contract, ticket).
- Documentation of recurring data flows to vendors (data-flow diagram or vendor register).
- Retention policy showing how long disclosure records are kept.
- Evidence of periodic review of the log (review ticket, sign-off, or commit history).
- Reconciliation between the vendor register and the disclosure log (no undocumented recipients).

## How a tiny AI-first startup satisfies it
- Maintain `compliance/disclosure-log.md` (or a sqlite table) with columns: date, recipient, data categories, subjects affected, basis, authorized_by, ticket link. Git history gives you tamper-evident timeliness for free.
- Cover recurring flows once: one row per vendor flow ("all user emails → Postmark, ongoing, basis: privacy policy §4"), referencing the vendor register.
- Log ad hoc disclosures via a Linear ticket template (`type:disclosure`) and require the log row in the PR/ticket before close.
- Quarterly, run a 15-minute review: diff the vendor register against the log, close a recurring Linear ticket as the review record.
- Include compelled disclosures (subpoenas) with legal basis; if none occurred, the empty-but-maintained log is still your evidence.

## Automated shadow checks

| Check | Source | Method |
|---|---|---|
| Disclosure log file exists with required columns | repo `compliance/disclosure-log.md` / sqlite | File existence + header/schema parse |
| Log updated during the period (not stale) | git history | `git log --format=%ci -- compliance/disclosure-log.md`, check recency |
| Every PI-receiving vendor in register has a recurring-flow row in log | register + log | Parse both, diff recipient sets |
| Ad hoc disclosure tickets in Linear each map to a log row | Linear API + log | Query `type:disclosure` issues, match ticket links in log |
| Quarterly review ticket completed | Linear API | Query recurring review issue, check done within quarter |
| Log entries accurate vs. actual data flows | production systems | MANUAL — auditor walkthrough/interview |

## Evidence artifacts
- `compliance/disclosure-log.md` or `disclosures` sqlite table, with git commit history.
- `compliance/vendors.md` vendor register (recipients of recurring flows).
- Linear tickets tagged `type:disclosure` with linked evidence.
- Quarterly disclosure-log review tickets (Linear) with completion dates.
- Retention policy section covering disclosure records (`compliance/policies/data-retention.md`).
